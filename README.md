# Мессенджер

Учебный проект мессенджера: TypeScript + Vite + Handlebars + PostCSS.
Спринт 3. Роутинг и работа с запросами.

## Команды

- `npm install` — установка зависимостей
- `npm run dev` — dev-сервер на http://localhost:3000
- `npm run build` — проверка типов и сборка в `dist`
- `npm run start` — сборка и запуск `vite preview` на 3000 порту
- `npm run lint` — ESLint
- `npm run lint:styles` — Stylelint

## Страницы

| Путь | Страница | Доступ |
|------|----------|--------|
| `/` | Вход | только без авторизации |
| `/sign-up` | Регистрация | только без авторизации |
| `/messenger` | Чаты | только с авторизацией |
| `/settings` | Настройки профиля | только с авторизацией |
| `/404` | Не найдено | всем |
| `/500` | Ошибка сервера | всем |

Неавторизованного пользователя роутер отправляет на `/`, авторизованного со входа и регистрации — в `/messenger`. Неизвестный адрес показывает страницу 404.

## API

Приложение работает с [API](https://ya-praktikum.tech/api/v2/swagger/#/): регистрация, вход и выход; изменение профиля, аватара и пароля; список чатов, поиск по названию, создание и удаление чата, добавление и удаление участников.

Для проверки используются только тестовые данные: никаких настоящих имён, почты и телефонов.

## Архитектура (MVC)

```
src/
  core/          Block, registerComponent, Router и Route, HTTPTransport, Store
  api/           Model: запросы к серверу — AuthAPI, UserAPI, ChatsAPI
  models/        Model: типы данных и экземпляр Store с состоянием приложения
  controllers/   Controller: AuthController, UserController, ChatController
  components/    View: Button, Input, Field, Avatar, Link, ChatItem, Message
  pages/         View: страницы, наследники Block
  utils/         валидация, формы, queryString, форматирование дат, renderDOM
  styles/        переменные и базовые стили
  router.ts      экземпляр роутера и список адресов
  main.ts        точка входа: регистрация маршрутов и проверка сессии
```

Каждый компонент и страница лежат в своей папке в одном формате: класс `.ts`, шаблон `.hbs`, стили `.pcss` и `index.ts` с экспортом.

Поток данных: страница вызывает контроллер → контроллер делает запрос через API и кладёт ответ в Store → страница подписана на Store и перерисовывается через `setProps`.

### Роутер

`Router` — синглтон по образцу из уроков: `use(path, Page, access)`, `start()`, `go()`, `back()`, `forward()`. История браузера работает через `pushState` и `popstate`, поэтому кнопки «Назад» и «Вперёд» и перезагрузка страницы показывают ту же страницу.

При переходе прошлая страница удаляется из DOM (`Route.leave` → `Block.destroy`), снимаются её обработчики и подписка на Store. Ссылки между страницами — компонент `Link`, который переходит через роутер без перезагрузки.

### HTTPTransport

Обёртка над `XMLHttpRequest` на промисах, без `fetch`. Методы `get`, `post`, `put`, `delete`. Для `GET` данные превращаются в query string (`utils/queryString.ts`), для остальных методов отправляются в теле: объект — как JSON, `FormData` — как есть (загрузка аватара). Ошибка сервера приходит как `HTTPError` со статусом и текстом из поля `reason`.

Общая обработка ошибок в `controllers/errors.ts`: ответ 401 отправляет на вход, 5xx — на страницу 500, остальные ошибки показываются под формой.

### Компоненты

Компонент наследуется от `Block` и регистрируется как Handlebars-хелпер. В шаблоне он вызывается так: `{{{ Button text="Войти" type="submit" }}}`. Внутри `{{#each}}` можно передать текущий элемент целиком: `{{{ ChatItem this }}}`.

Жизненный цикл: `componentDidMount`, `componentWillUnmount`. Вызов `setProps` обновляет props и перерисовывает компонент. События задаются в поле `events` и навешиваются на корневой элемент компонента.

### Формы и валидация

- Правила на регулярных выражениях описаны один раз в `utils/validation.ts` и используются во всех формах.
- Поле проверяется на `blur`, вся форма — на `submit`.
- При отправке страница не перезагружается (`preventDefault`), а в консоль выводится объект со всеми полями формы.
- Ошибки сервера и подтверждения выводятся под формой через `textContent`.
